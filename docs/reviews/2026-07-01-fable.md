# Design Review — Foundation for "spec → software, faster & cheaper" (2026-07-01, Fable)

## Verdict

The engine/adapter split is a sound foundation and worth protecting — but you have built
an excellent **control plane** and almost no **data plane**. The WorkItem/StageResult seam
is the right seam; what travels over it is anemic: stage outputs are dropped on the floor
(`scope`'s `plan` never reaches `implement`'s prompt — `render_prompt` takes only
title/body/learnings, `orchestrator/stages.py:110`; `_absorb_outputs` lifts only
`pr_number`/`pr_url`, `orchestrator/state_machine.py:101` — `intake`'s worktree/branch
reaches no one), the ProjectConfig command surface (`install_cmd`, `test_unit_cmd`,
`typecheck_cmd`, `adapters/project/base.py:46–51`) is declared, scaffolded, and consumed
by nothing at dispatch time, and every stage is a fresh agent context that re-discovers
the repo from scratch (`run_targets/workflow_shim.js:65`). The system works live because
frontier agents can rediscover state each stage — which is precisely the "slower and more
expensive" the goal exists to eliminate. The single most important thing to change: give
the contract a data plane — a task-scoped context that absorbs *all* stage outputs and is
threaded into downstream WorkItems — **before** building the spec→DAG front door, because
decomposition emits exactly the artifacts today's pipeline structurally discards. The
single thing to protect: engine-never-calls-a-model determinism plus the durable-artifact
discipline (resume, attribution, replayability) — it is the moat over "just script the
Agent SDK," and every capability below builds on it safely. The 6-stage collapse is right
as a collapse but wrong as a hard enum; the "cheaper via prompt-cache reuse" thesis
currently has a measurement and no mechanism, and the measurement is blind on the one
lane you actually run.

---

## Foundation analysis — the three bets

### Bet (a): the engine-never-calls-a-model WorkItem/StageResult contract — HOLDS, but it is control-plane only

**Steelman.** This bet has already paid out and the retrospective is right to bank it:
171 tests without a live model; interchangeable lanes proven by the interactive≡headless
conformance test; resume-by-construction (a session death leaves a WorkItem un-recorded
or a StageResult recorded, never a half-counted stage); attribution structural
(`engine.record` is the only advance path, `orchestrator/engine.py:226`); the replay/lease
hardening (`pending_work_item_id`, content-hash + stage/model/attempt binding,
`engine.py:230–262`) is genuinely good engineering. For provider parity, parallel scale,
and unattended mode, this seam is exactly what you want.

**Where it breaks as the goal's capabilities land.** The contract carries *dispatch*
information (prompt, model, lane, schema_ref) but no *task data*. Three consequences,
in increasing severity:

1. **Cross-stage context is discarded.** `next_work` renders every prompt from
   `task_id + title + body + learnings` (`engine.py:174–177`). The scope stage's entire
   reasoning product — the plan the schema requires (`schemas/stages/scope.json`) — is
   written to the stage record and never read again. `review` is told "Review the PR"
   without being given `task.pr_url`. Each downstream agent re-derives upstream work,
   paying tokens and injecting drift (implement can silently diverge from the plan scope
   produced; nothing would notice).
2. **Project knowledge doesn't reach the headless lane at all.** On interactive, the
   seeded `.claude/` kit + session CWD smuggle project context in out-of-band. On
   headless, `claude_cli_transport` shells `claude -p` from whatever CWD the process
   has — `WorkItem` has no `cwd`/worktree field (`orchestrator/schemas/work.py:76–136`)
   and the prompt names no repo, no test commands, no conventions. The `--agent` persona
   is the *only* working channel of project knowledge, and codex gets even that only via
   the still-unbuilt AGENTS.md item (roadmap E).
3. **Spec→software runs on data flow.** Decomposition emits a task graph *with per-task
   context* (which part of the spec, which interfaces, what the siblings are doing). A
   contract that drops `scope.plan` today will drop the decomposer's output tomorrow.
   This is why the data plane is the critical-path item, not a cleanup.

**The invariant that's assumed-but-not-enforced:** *"the runner's environment supplies
whatever context the prompt lacks."* True only on interactive×claude inside the project's
own session with a seeded kit. Nothing asserts it; the headless and codex lanes silently
violate it. Related and concrete: `WorkItem.timeout_s` is never set — `next_work` omits
it (`engine.py:179–191`), so both real transports run `subprocess.run(timeout=None)` and
a hung CLI hangs the scheduler thread forever, despite the comment claiming the opposite
(`adapters/execution/transport.py:132`). That is the one bug-severity item in this review.

**Load-bearing vs decorative.** Load-bearing: WorkItem/StageResult + the lease/replay
checks, the status store + resume cursor, the DAG (`transitive_cascade` is clean), the
cost ledger's one-row-per-call. Decorative today: the ProjectConfig command surface (see
above); `FailureClassifier` (an interface with a heysoo impl that the engine never
invokes — the infra-reset loop it exists for is unwired, per your own DEFERRED row);
`CapabilityDescriptor.supports_streaming`/`cost_metered` (never read by anything);
`Engine.ready()` (`engine.py:126`), which duplicates `Scheduler.dispatchable` with
*different* semantics (PENDING/BLOCKED-only vs non-terminal-without-lease) — one of them
is wrong whenever they disagree; pick one. Decorative isn't fatal, but each decorative
surface is maintenance drag and a false signal of capability — delete or wire them.

### Bet (b): the collapse to 6 stages — right collapse, wrong rigidity

**Steelman.** Collapsing research/evaluate/plan into one `scope` call is where the real
session reuse lives: one agent context does the whole reasoning arc. It matches how
frontier models actually work (goal + constraints beats enumerated micro-steps), it cut
the schema/state surface by half, and it's live-proven. Correct call.

**Stress test, two findings:**

1. **The collapse outsourced the engine's governance.** All the adaptive loops
   (quality iteration, test/fix cycles, review convergence) now live *inside* a single
   opaque agent call. The engine's sophisticated machinery — structured-signature
   breaker, retry-with-learnings, per-call cost rows — operates only at whole-stage
   granularity, where each attempt is a full macro-stage re-run. There is no
   per-iteration cost visibility, no convergence detection (target §6.2's "wired into
   implement, review AND test" did not survive into the build — your DEFERRED review-loop
   row admits it), and no way for the engine to stop a stage that is thrashing
   internally. This is an acceptable trade *today*; be honest that the engine governs
   the seams between six black boxes, not the work. The lever that restores visibility
   without re-fragmenting the pipeline is roadmap D's workflows-inside-stages: a stage
   that is itself a find→verify workflow reports per-iteration structure back through
   `structured_output`.
2. **The hard `Stage` enum bakes "one issue → one linear PR pipeline" into every
   schema.** `STAGE_ORDER`, `LANE_STAGES`, `Task.stages` keyed by all six — the linear
   shape is load-bearing in the schemas, and it is the wrong shape for the goal's node
   types (a decomposition task, a design task, an integration/acceptance gate, a docs
   task do not want intake→scope→implement→test→deliver→review). You already have the
   escape hatch: lanes *are* named stage subsets (`LANE_STAGES`). Generalize lane →
   per-task pipeline (a task carries its stage list; the enum becomes a vocabulary, not
   a sequence) while the schema count is small and there is one migration to write. Do
   not build heterogeneous node types *now*; do stop treating the sequence as a global
   constant so the migration stays one schema bump instead of a rewrite.

### Bet (c): "cheaper via single-session prompt-cache reuse" — a ledger without a mechanism

**Steelman.** The within-stage half is real: collapsing three reasoning stages into one
`scope` call is genuine reuse (one context, no re-reading). `CostLedger.analysis()`'s
cache-read-savings-net-of-write-premium counterfactual (`orchestrator/cost_ledger.py:100`)
is the right measurement design. And interactive×claude on subscription makes marginal
cost ≈ 0, which is a legitimate "cheaper."

**Where it's currently fiction:**

- **No cross-stage mechanism exists.** The shim dispatches a *fresh* `agent()` per
  WorkItem (`workflow_shim.js:65`); the six prompts are terse and share no engineered
  prefix (`stages.py:28–107`); the per-stage WorkItem boundary structurally *prevents*
  session continuity. Whatever `cache_read` tokens the ledger sees are the harness's
  incidental system-prompt caching, not your design. The thesis's named mechanism —
  §6.5's "chain collapsed stages in one session" — was never built across stages.
- **The measurement is blind exactly where you run.** The shim's token capture is
  speculative (`res && res.__usage`, `workflow_shim.js:72–77`, with a comment conceding
  it "may be uncapturable in-sandbox"). On the default lane the ledger most likely
  records zeros, so `session_reuse.win_pct` on a real run is an artifact. Before any
  cost-optimization work (roadmap C1), fix measurement integrity — otherwise you will
  tune routing policy with blind instruments.
- **What "cheaper" actually is today:** subscription arbitrage + role tiering
  (`model_table.py:42–46`). Say that plainly and defend it — it's a fine answer — but
  the *engineered* version of cheaper is the data plane (kill per-stage rediscovery)
  plus headless session continuity (innovation #1 below), which turns the cache thesis
  from a slogan into a mechanism.

Also filed under (c): `model_table` is claude-only and module-global (`_MODELS`,
`model_table.py:36–49`), so a codex-routed stage gets a claude model id shelled to
`codex exec -m` and priced from the claude table — you know this (roadmap E1); it is a
correctness bug on an advertised lane, and `ledger.record` raises `KeyError` on any
model id outside the table, unlike the tolerant `analysis()`. Small fix, do it early.

## Critical path & roadmap triage

**Build first: the task context plane.** One change, three payoffs. Concretely:
`_absorb_outputs` generalizes to fold every stage's `structured_output` into a
`task.context` (a bounded, engine-owned dict: plan, worktree/branch, pr_url, failures,
validation_notes); `render_prompt` gains a stable, cache-friendly context block
(task context + spec excerpt + the ProjectConfig commands that are currently
decorative); `WorkItem` gains `cwd`/worktree so the headless lane stops depending on
process CWD. Why first: it is the *cheaper* lever (ends per-stage rediscovery), the
*quality* lever (implement actually follows scope's plan; review actually sees the PR),
and the *prerequisite* for decomposition (the front door emits context; today the
pipeline can't consume it). It is additive to the seam — no rewrite.

**Then, in order:**
1. **Spec → task-graph decomposition (roadmap B1) + follow-up task creation (A1) as one
   build.** Both need `TaskSource.create_task(spec)`; the DAG, `add_task`, and the
   scheduler already run arbitrary graphs, so the front door is a decomposition stage
   whose output is fed through create_task with `depends_on` — with human approval of
   the emitted graph as a hard gate. This is remarkably cheap given what exists.
2. **Acceptance gate (B2)** as a run-scoped final task depending on all leaves — the DAG
   already expresses it; no new machinery.
3. **Unattended queue mode + parallel headless worktrees** (the promoted DEFERRED row +
   C2) — the "faster" lever; worktree isolation becomes real instead of aspirational
   once WorkItem carries `cwd`.
4. **Provider-aware model table (E1)** — small, correctness, unblocks codex as a real lane.
5. **Interactive usage capture** (or an honest supervisor-side reconciliation) — before
   any cost-policy work.

**On-path roadmap items:** A1 (merged into #1 above), B1–B3, C2, E1, E2, D
reasoning-effort-per-stage (cheap, real), D workflows-inside-stages (the quality lever
that also restores engine visibility into loops — schedule it with the deferred
independent-reviewer half of test-validate; they are the same build).

**Distractions / premature:**
- **Meta-authoring layer (A4).** Re-evaluating it is fine; building it is premature and
  the reference's own history says it was open-loop tooling. An agent that edits the
  orchestrator without an eval harness (below) is a risk generator, not self-improvement.
- **Cross-run learnings KB (A5)** — premature *until the context plane exists*: a KB is
  an injection problem, and today there is nowhere to inject. Build it right after, not
  before.
- **Cost-optimizing routing policy (C1)** — premature while the default lane records
  zero tokens. Instruments first.
- **MCP servers replacing `gh`/`git`, custom slash commands, vision drop-in** — fine DX,
  not on the path; do them opportunistically or not at all.
- **A-priori cost estimation (B3)** — keep it to a crude per-stage prior from ledger
  history + a budget cap; a sophisticated estimator before the eval corpus exists would
  be fiction with decimal points.

**Missing from the roadmap entirely:**
1. **The context plane itself** — nothing in the roadmap names "stage outputs don't flow
   downstream"; D's prompt-cache structuring circles it but frames it as caching.
2. **An eval/replay bench for the harness.** The entire self-improvement section has no
   way to know whether any change made the system better, faster, or cheaper. You have
   61 real run logs and a runner-injectable scheduler — see innovation #2.
3. **Human approval as a mechanism, not a norm.** The HARD CHECKPOINT lives in CLAUDE.md
   and skill prose. Spec→software needs `blocked_on_human` as a task state with an
   approval artifact (approve the decomposed graph, approve the budget, approve merge) —
   otherwise autonomy scales past your only safety gate.
4. **Timeout wiring** (the bug above) + stage-level timeout defaults in `STAGE_SPECS`.

## Innovations (net-new, ranked by impact × novelty)

1. **Per-task session continuity on the headless lane** — *safe-bet.* Chain one task's
   six stages through a single `claude` conversation (`--resume`/session-id): `WorkItem`
   gains an optional `session_ref` the engine threads per task; the transport resumes
   instead of cold-starting. The engine stays deterministic — a session ref is routing
   metadata, and a resume-after-crash simply starts a fresh session (correctness never
   depends on continuity). Payoff: implement sees scope's *full reasoning*, not a
   re-rendered summary; the prompt-cache thesis finally gets its mechanism (every stage
   after the first is nearly all cache-read); rediscovery cost drops to ~zero. This is
   the single biggest faster+cheaper move available, and it is a transport-layer change.
2. **A replay/eval bench built from your own durable artifacts** — *safe-bet.* The
   scheduler already accepts injected runners; recorded StageResults + the 61-run heysoo
   log corpus give you golden tasks. Build `orchestrator bench`: replay recorded runs
   through engine changes (regression: same transitions, same cost math), plus a small
   live suite (5–10 curated issues) with cost/wall-clock/PR-outcome metrics per harness
   version. Every self-improvement idea in roadmap A is unjudgeable without this; with
   it, "did that change help" becomes a command instead of a vibe. This is the missing
   keystone of the whole self-improvement arc.
3. **Contract-first parallelization** — *big-swing.* The DAG serializes on task
   completion; real teams parallelize on *interfaces*. Have decomposition emit, for each
   dependency edge, an interface-contract task (stub + contract tests) that completes
   fast; dependents depend on the *contract* task, not the implementation task, and the
   implementation must keep the contract tests green. DAG width — and therefore
   wall-clock on a real spec — improves qualitatively, and the acceptance gate (B2)
   inherits machine-checkable seams. Needs the context plane + decomposition first;
   this is what makes "faster" scale past trivially-independent tasks.
4. **Failure-driven task fission** — *big-swing.* Today a breaker trip is terminal and
   cascades. Add a `decompose` remediation: when a task fails the breaker, dispatch one
   scope-class WorkItem that splits it into smaller tasks with `depends_on`, feed them
   through `create_task` into the same run, and cascade only if fission fails too. The
   scheduler already tolerates tasks added mid-run. This converts your most expensive
   failure mode (dead task + blocked subtree) into adaptive granularity — and it is the
   self-healing counterpart of the spec→DAG front door, sharing all its machinery.
5. **Stage-commit checkpoint protocol** — *safe-bet.* Make git effects part of the
   contract: every stage success ends in a tagged commit (`task/<id>/<stage>/<attempt>`)
   recorded in the StageResult; retries reset the worktree to the last-good tag instead
   of retrying over dirty state; resume checks the tag before re-dispatching. This
   solves your DEFERRED committed-work/timeout-recovery row *generally* (it is currently
   framed as a special case), makes attempts actually idempotent (today a failed
   implement leaves debris the retry inherits silently), and gives the ledger a
   work-product anchor per stage.

## What you're fooling yourselves about

1. **"Cheaper" is currently subscription arbitrage, and your meter is blind.** The
   session-reuse win the ledger reports is measuring incidental harness caching through
   a shim that probably records zero tokens on the default lane. Nobody has engineered
   the mechanism the thesis names. Until #1/#2 above land, the honest cost story is
   "runs on a subscription, tiers models by role."
2. **The engine governs less than its polish suggests.** 171 green tests cover the
   deterministic shell exhaustively — and the product's actual behavior lives in ~100
   lines of terse, untested prompt templates plus whatever the agents decide inside six
   opaque calls. The breaker, capacity math, and lease discipline are real; they are
   also the *easy* 20%. The system's quality ceiling is set by the prompts and the
   in-stage loops the engine cannot see.
3. **Project-agnosticism is mostly aspiration at execution time.** The adapter that
   matters at dispatch is a task source + an agent-name lookup. The command surface,
   taxonomy, and classifier — the things the §5 design says make a repo pluggable — are
   dead weight until the context plane threads them into prompts. The headless lane, the
   one you advertise as "always works," currently receives no project knowledge at all.
4. **The pipeline grades its own homework.** `review` is a same-harness agent
   self-reporting `approved`, and `tests_meaningful` is a self-affirmation the gate
   fail-opens on. You know this (the deferred reviewer-half) — but for a system whose
   goal is *unattended* spec→software, an independent gate isn't a deferred nicety, it
   is the difference between automation and auto-approval.
5. **It earns its existence over scripting the Agent SDK — narrowly, and only if you
   defend the right thing.** The moat is the durable-artifact contract: resumable,
   attributable, replayable runs. It is not the volume of engine code. Every decorative
   surface (unwired classifier, unread capability flags, duplicate ready-paths) moves
   you toward being a framework instead of a harness. Delete faster than you accrete —
   the goal needs a data plane, an eval loop, and a front door, not a bigger engine.
